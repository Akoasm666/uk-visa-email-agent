# S1 集成验收项（W00 文档约定，接线在 S1）

以下约定在 W00 冻结输入来源与验收意图；**实际持久化接线与集成测试在 S1 完成**。

## 输入来源（不得由调用方口头传入冒充）

| 门禁字段 | 权威来源 | 说明 |
|---|---|---|
| 人工接管下的发送批准 `human_send_approved` | 后台发件任务批准记录 | 必须匹配**当前** `outbox_id` / 发件任务；不得用会话参数伪造 |
| 最终包 `package_kind` | 同案已保存的交付包记录 | 来自 delivery 模块落库结果 |
| 附件清单 / 文件哈希 | 同案已保存的材料包清单 | 与 `package_id` 同一版本快照 |
| 最终包审批 | 同案审核记录 | 绑定 `case_version` + `package_id` + 收件人集合 |
| 客户确认 / 最终审批版本 | 同案确认与审核记录 | 供 `TransitionContext` |
| `resume_status` | 进入 `issue_resolution` 时写入的案件字段 | 离开问题态时读取 |
| `delivery_id` / 收件确认 | 出站记录与客户确认事件 | `receipt_for_delivery_id` 必须等于本次交付 |

## S1 必须用集成测试覆盖的拒绝场景

1. **旧批准**：审批绑定旧 `case_version` 或旧 `outbox_id` → 无法发送  
2. **错包**：审批 `package_id` 与发件箱材料包不一致 → 无法发送  
3. **校验后换附件**：门禁通过后、实际发送前替换附件清单 → 发送前再校验失败并拒绝  
4. **接管伪造**：请求体声称已批准但后台无匹配当前发件任务的批准记录 → 拒绝  

单元契约测试（W00）只覆盖纯函数门禁；上述端到端行为以 S1 集成为准。
