# 顾问工作台改进建议

顾问打开案件，应该马上看懂在等谁、还差什么、现在能做什么。用本地工作台核对了列表和收件箱，并用合成案件渲染了详情页。

## 先删掉顾问用不上的东西

| 现在看得到 | 建议怎么减 |
|---|---|
| 首页的完整「新建案件」表单、介绍「可搜索 / 按进度与签证筛选」的文字、每行的短案件号和「打开」按钮 | 首页留一个「新建案件」入口，点开再填表。删掉介绍文字和重复的「打开」，点案件名即可进入。案件号仍可用于搜索，平时放进详情。 |
| 详情顶栏和正文各写一次案件名。「进度」「今天要做什么」和「顾问处理区」会分别讲同一个问题 | 案件名留一次。进度留一个短标签，顶部只写具体要做的事。同一待办只出现一次，点开直达处理位置。没有待办就省掉空区块和「继续下一步」。 |
| 「在等客户」「等客户补件：护照」「1 份材料待验收」可以挤在一起 | 同一件事留一条具体状态。等重传就写「等客户重传护照」，收到新版就写「新版护照待顾问核对」。遇到两件不同的事，再分别列出。 |
| 收件箱的「顾问提醒 · X」、正文「共 X 条」、「顾问收件箱」小标题与长说明。每行还有案件名和「去案件处理」两个入口 | 标题用「待处理来信」，保留一处准确的待办数和一个处理入口。把「收件记录 ID」挪到邮件详情的排查信息，列表只留发件人、主题和待处理原因。 |
| 同一文件在「顾问处理区」和「未归类材料」重复出现。清单每项还有一套「从本地选择文件 / 上传」 | 文件只在材料区列一次，待办点过去归类。把一排上传表单收成一个「手动添加材料」入口，需要时再选材料类型。 |
| 文件旁的「AI已读」、预览页的 `application/pdf` 等技术格式，以及预览失败时两处「下载」 | 日常看「待核对」「顾问已验收」或退回原因。技术格式放文件详情，预览页留一个下载按钮。 |
| 「确认与终审 · vX」以及「材料大改，旧确认作废」「允许重开已关闭案件」 | 当前审核结果留在审核区，版本号和历史放在可展开的记录里。「重开」仅在已关闭案件出现，手动作废旧确认放维护入口。需要顾问接管时，在待办旁给出「接管」或「交还」。 |

**精简后的首页**保留待处理案件、搜索筛选和新建入口。列表一行只需案件名、签证类型和当前卡在哪里。

**精简后的案件详情**保留客户和签证类型、当前要做的事、邮件和材料、审核与发送。发信前能看到实际收件人、正文和这次要用的附件。发信后能看到真实发送结果，历史记录需要时可展开。

验收时，看一个有待归类文件的案件，文件和归类按钮都只出现一次。查看正常办理中的案件时，页面没有重开按钮。打开最终发送页，仍能核对收件人、附件和审批是否有效。

## 1. 让「下一步」跟着待办走

目前，「在等客户」和「材料差不多了，去写说明」可以同时出现。前者只显示一个等待标记，后者只切换案件阶段。「说明写好了，发给客户确认」也只切换阶段，没生成草稿时就可能出现。

建议把状态写成「等客户重传护照资料页」「收到新版护照，等顾问核对」这类具体的话。收齐后更新等待状态。有待办就给出对应操作。需要准备邮件时，用「生成客户邮件草稿」，实际发送另有明确的按钮和结果。 [待办和按钮](../src/visa_agent/workbench/pages.py#L764) · [阶段切换](../src/visa_agent/fastapi_app.py#L1787)

验收时，依次查看等客户、收到新材料、需要顾问核对这三个状态。每次进入案件都能看懂当前该做什么，按钮做的事与文案一致。

## 2. 让收件箱里的事能办完

「待核对归属的来信」目前只显示发件人、主题和记录编号，顾问无法在这一页打开邮件或把它归到案件。「标为已处理」一点就会关闭待办，对尚未审核或答复的问题也有这个按钮。

建议让顾问打开原邮件和附件，确认后选案件归档。其他待办直接跳到具体文件或客户问题，将「已解决」和「无需处理」分开，选择后者时留下原因。 [收件箱](../src/visa_agent/workbench/pages.py#L475) · [关闭待办](../src/visa_agent/case_service/remediation.py#L277)

验收时，用一封无法自动归案的合成来信，从收件箱找到内容、选中正确案件并完成归档。关闭一条无需处理的待办后，案件里能查到原因。

## 3. 在一个地方核对材料

同一份未归类文件可能在「顾问处理区」和「材料清单」各出现一套归类按钮。清单还会把尚未判断是否适用的项目标成「还缺」，「AI已读」和「已验收」也很容易被扫成同一件事。

建议每份文件只留一个处理入口，从待办直接定位过去。在同一处查看原件、旧版与新版、退回原因和处理结果。清单明确写「待判断是否适用」「已收到，待顾问核对」「顾问已验收」。 [材料清单](../src/visa_agent/workbench/pages.py#L957) · [顾问处理区](../src/visa_agent/workbench/pages.py#L1098)

验收时，同一份文件只需归类一次。当客户重传护照时，顾问可以很快分清哪份是新版、哪份有问题，以及哪份可以放进最终材料包。

## 4. 看着实际文件审批和发信

目前，「终审通过」记录案件层面的决定，页面上看不到要发给谁、要发哪一版材料、实际有哪些附件。「标记为已发出」也只推进案件阶段。组包、指定材料包审批和发送已有后台接口，尚未连成顾问可操作的页面。

建议新增一个审核和发送区，先展示收件人、邮件正文和附件，再批准这一版材料包并发送。材料更新时提示「旧审批已失效，请重新审核」。发出后显示实际发送结果，收到客户回复后再记录回执。 [工作台终审](../src/visa_agent/fastapi_app.py#L1847) · [材料包接口](../src/visa_agent/fastapi_app.py#L1238)

验收时，对同一案件依次尝试未审批发送、审批后换附件、重新审批后发送。前两次应说明卡在哪里，最后一次可核对邮件收件人和附件。

## 5. 首页让顾问先找到要处理的案件

首页最上面是开案表单。同一个空白提示既用于「还没有案件」，也用于搜索无结果。列表最多取 100 条，却用「共 X 条」来显示本次取到的数量。点「新建」还可能立即给客户发首封邮件。

建议让「待我处理」和搜索靠前，新建案件放在独立入口。分别提示「还没有案件」和「没有符合条件的案件」。支持翻页，并让开案按钮明确写出「新建并发送首封邮件」。 [案件列表](../src/visa_agent/workbench/pages.py#L566) · [列表与开案操作](../src/visa_agent/fastapi_app.py#L1493)

验收时，分别打开空库、筛选无结果和超过 100 条的列表。顾问能分清三种情况，也知道点开案按钮会发邮件。
