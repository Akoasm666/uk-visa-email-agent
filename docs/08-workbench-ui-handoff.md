# 顾问工作台 UI 交接

用户希望工作台简洁直白，打开案件就知道在等谁、还要做什么。本次整理交接，由用户另开会话修改页面。前一轮已把开案表单折叠，合并重复待办，并把手动上传和文件归类各收成一个入口。其他问题和验收例子见 [工作台改进建议](07-workbench-ux-review.md)。

## 截图里的三个项目

| 屏幕上看到的内容 | 实际行为 |
|---|---|
| 「等客户回复」 | 显示案件的等待标记。这个标记独立于案件阶段，所以会跟下面的按钮同时出现。 |
| 「生成客户说明」 | 在「写客户说明中」阶段出现。它用合成资料生成并保存通用客户说明草稿，不发邮件，也不推进阶段。 |
| 「进入客户确认阶段」 | 把案件从「写客户说明中」切到「等客户确认」，不会生成草稿或发邮件。 |

[待办显示](../src/visa_agent/workbench/pages.py#L730) · [按钮定义](../src/visa_agent/workbench/pages.py#L1133) · [生成草稿](../src/visa_agent/ai_capabilities/draft.py#L203) · [阶段切换](../src/visa_agent/fastapi_app.py#L1787)

这两个按钮对应旧的通用说明流程。**行程单确认**有自己的草案和客户邮件回复，应该在「行程单」区展示当前版本、是否发出和是否确认。

改页面时，把「下一步」留给当前真能办的事。等客户补材料或确认行程时，写清具体在等什么。通用说明如果还有使用场景，放到「客户邮件草稿」区，清楚区分「生成草稿」「发给客户」「客户已确认」。单纯切换阶段的按钮可以从日常待办里移开。

## 现有改动与接线进度

| 功能 | 已做 | 还差 |
|---|---|---|
| 行程单 | 案件页已显示当前草案、版本和确认状态。发件服务接受后显示「等客户确认」，来自旧版邮件的回复无法确认新版。修改日期或活动会替换工作台的当前草案，并重新发信请客户确认。 | 已用真实邮件发出第 1 版。修改与确认已用隔离测试覆盖，仍可用真实邮件复验。 |
| 删除材料 | 案件页展开「删除材料」后可确认移除。后端检查案件版本，将材料移出当前清单并让旧确认失效。原件和已交付记录留作审计。已关闭、已完成和已发送待回执的案件隐藏删除入口。 | 可用合成材料在新版界面重走一次，确认操作入口符合顾问习惯。 |

[案件页模板](../src/visa_agent/workbench/pages.py#L1239) · [案件页接口](../src/visa_agent/fastapi_app.py#L1684) · [数据库字段](../src/visa_agent/storage/schema.sql#L431) · [删除服务](../src/visa_agent/document_pipeline/service.py#L484)

页面和后端已接通。后续改界面时可继续用以下方式验收。

1. 等客户时页面说清等什么，只切阶段的按钮不会被理解成已经发信。
2. 案件页能看到当前版行程单。邮件实际发出后才显示「等客户确认」，旧版本的回复不能确认新版。
3. 取消删除时材料仍在。确认删除后材料从当前清单消失，已交付记录仍可查。
